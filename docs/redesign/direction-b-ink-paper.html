The handler passes req.params.id straight into findById, so Mongoose throws a CastError for anything that isn't 24 hex characters. The error middleware only knows HttpError, so the cast error falls through to the generic 500.

Cheapest correct fix: validate at the edge, reuse HttpError so the response shape stays { error: { code, message } }.

Ink & Paper

An editorial system for a coding agent. The conversation is set like a document: a serif for prose, SF Pro for interface, SF Mono for code and metadata. Structure comes from hairline rules, dot leaders and numbered sections - not from boxes and fills. Metadata lives in the margin.

§ 5Motifs
  • Marginal notesA 104px right-aligned margin carries who, when, how long and how much - speaker labels, times, section numbers, durations. The measure stays pure prose.
  • Hairlines, not boxes1px rules separate turns, tool rows and file lists. A heavier ink rule opens a listing or a change set; a double rule marks anything that needs your decision.
  • Dot leadersTitles run to their figures across a dotted leader, as in a table of contents - "Ran 4 commands ....... 9.4s".
  • Numbered sectionsTool groups are sections (§ 1, § 3) and each step is a sub-clause (1.4, 3.2) so a turn can be cited precisely.
  • Figures and listingsAttachments become "Fig. 1", code blocks become "Listing 2" with a caption line; the user's prompt is a quotation set against an ink rule.
  • Reasoning in italicThoughts and live subagent activity are set in the serif italic - the voice of the working notes, visibly quieter than the answer.
