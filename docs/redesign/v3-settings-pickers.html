Oorders-api/Idempotency keys for POST /orders
Retries of POST /orders from the mobile app create duplicate orders. Why?

The app times out after 5 s, but createOrder still commits, so every retry inserts a new row.

Add Idempotency-Key support as middleware and cover it with tests.

Added an idempotency middleware that stores the first response for each Idempotency-Key for 24 hours and replays it on retry. It is mounted only on the create route in orders.ts:

router.post("/orders", requireAuth,
  idempotency({ ttlSeconds: 86_400 }), createOrder);

Reusing a key with a different body now returns 422. All 14 tests in orders.test.ts pass.
