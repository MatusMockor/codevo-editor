The handler inserts a new row on every request and nothing ties a retry to the original call. When the client times out after the insert commits, its retry creates a second order. The usual fix is an Idempotency-Key header stored alongside the response.

Added an idempotency middleware. A repeated Idempotency-Key within 24 hours now returns the stored response instead of creating a new order.

router.post("/orders", idempotency({ ttl: "24h" }), async (req, res) => {
  const order = await orders.create(req.body);
  res.status(201).json(order);
});
