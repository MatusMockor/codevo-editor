This baseline is captured by running `node tools/vscode-baseline/run.mjs`, which drives two disposable VS Code Extension Development Host windows, one over `perf/fixtures/large-files` and one over `perf/fixtures/monorepo`, via `--disable-extensions --extensionDevelopmentPath=tools/vscode-baseline` against an isolated per-run `--user-data-dir`/`--extensions-dir` profile (seeded with `chat.disableAIFeatures: true` and workspace trust disabled so the isolated profile's first-run Copilot sign-in prompt and trust dialog never block the automation); it measures the same scenario ids as the Codevo CDP perf runner using the closest available VS Code API per scenario, documented per entry by the `method` field because some behaviors are not directly scriptable (Quick Open ranking is approximated by an `executeCommand`-free `vscode.workspace.findFiles` enumeration proxy) or measure dispatch latency rather than paint/frame time (`type-command-await`), then writes `perf/baselines/vscode.json`. `definition-large-20k`/`references-large-20k`/`rename-large-20k` sample 10 different `*Kind` type declarations spread across `large-20k.ts` (not the same query repeated) and `completion-large-20k` triggers global, unfiltered-scope completion at a blank line so each repetition performs real language-service work; every one of the 10 repetitions of every provider scenario must individually return a non-empty result (a definition/reference array, a completion list, or a rename edit with entries) - one empty repetition converts the whole scenario to a `{ id, error }` entry instead of silently accepting a suspiciously-instant, no-op measurement - and the per-repetition result count is recorded alongside the timing in each entry's `resultCounts` array so the committed JSON itself is evidence the work happened, not just the timing.

Captured 2026-07-31 with VS Code 1.131.0 (commit `e4c7e7b1d6d060162f4aa7f8225271b67ce1df75`) on macOS 26.5.2, arm64 (Apple Silicon), against the fixtures generated by `npm run perf:fixtures`. `references-large-20k` and `rename-large-20k` land in the low single-digit milliseconds because the fixture's `*Kind` types are declared and used only within a single self-contained file (no cross-file imports), so TypeScript's language service resolves them from an already-warm per-file symbol table; this was verified to be real (non-empty on every repetition, assertion-checked, `resultCounts` all greater than zero) work rather than a no-op short-circuit, not a measurement bug.

Honesty note on provenance: the committed capture was produced by launching `code` directly (twice, once per fixture root, with the same flags, isolated profile, and env var `run.mjs` uses internally) rather than by an end-to-end `node tools/vscode-baseline/run.mjs` invocation, because in this agent's sandboxed execution environment a `code` process spawned from inside a nested Node child process was silently killed before completing, while the identical command issued as a direct shell command was not. `run.mjs` itself contains the same logic and is expected to work unmodified from an ordinary interactive terminal or CI runner, but that end-to-end path has not been independently verified in this environment.
